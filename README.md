# Эпоха в коде — мини-сайт для GitHub Pages

Готовая статическая витрина 24 учебных проектов Кемеровского государственного университета: направление «Прикладная информатика в экономике», дисциплина «Программирование», 1 курс, 1 семестр. Проекты собраны в одну длинную таблицу на главной странице. Опубликованные сайты встроены в строки как мини-превью; рядом находятся подпись автора, ссылки и кнопка лайка. Оценки и внутренние комментарии преподавателя не публикуются.

## Подключение Google Таблицы для лайков

Таблица остаётся приватной. Публичная страница общается только с Apps Script Web App: он принимает лайк, хранит один активный выбор на браузер и отдаёт сайту агрегированные счётчики.

1. Создайте новую Google Таблицу. Оставьте доступ к ней только себе/организаторам.
2. В таблице откройте **Расширения → Apps Script**. Замените содержимое `Code.gs` кодом из `google-apps-script/Code.gs`.
3. Выберите функцию `setup` и запустите её один раз. Подтвердите доступ скрипта к этой таблице. Появится лист «Голоса».
4. Нажмите **Развернуть → Новое развертывание → Веб-приложение**. Выполнение — **от имени владельца**, доступ — **всем**. Опубликуйте и скопируйте URL веб-приложения, который заканчивается на `/exec`.
5. В `app.js` укажите этот адрес: `const VOTE_API_URL = "https://script.google.com/macros/s/.../exec";`.
6. Опубликуйте обновлённую папку через GitHub Pages. В каждой строке появятся рабочие лайки и счётчики.

Скрипт записывает хеш браузерного токена, ID проекта и время последнего изменения выбора. Сырые токены, имена и адреса электронной почты в таблицу не отправляются. Повторный лайк той же работы снимается; лайк другой работы переносит голос, не увеличивая общий счётчик голосов.

Защита намеренно лёгкая: токен хранится в локальном профиле браузера, поэтому очистка данных/режим инкогнито позволяют проголосовать ещё раз. Это отсечёт случайные повторные клики, но не является проверкой личности и не остановит целенаправленную накрутку. Для более строгого режима понадобится вход в аккаунт или отдельная система проверки.

## Публикация на GitHub Pages

1. Скопируйте содержимое этой папки в отдельный GitHub-репозиторий. Для публикации из подпапки `docs/` поместите туда всё содержимое целиком.
2. Откройте **Settings → Pages** и выберите публикацию из нужной ветки и папки (`/ (root)` или `/docs`).
3. Сохраните настройки. Рядом должны лежать `index.html`, `styles.css` и `app.js`.

Сборка и отдельный сервер для публикации не нужны. Лайки останутся выключенными, пока в `app.js` не будет добавлен URL Apps Script.

## Перед публикацией

- Подтвердите у студентов выбранный публичный формат подписи «имя + первая буква фамилии».
- Проверьте ссылки на сайты: авторы могут менять или снимать публикации.
- Если сайт запрещает отображение внутри iframe, в строке останется рабочая ссылка «Открыть сайт».
- Для одной работы, сданной в DOCX без опубликованного сайта, предусмотрен архивный превью-блок и ссылка на оригинал.
